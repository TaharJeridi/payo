# TAH-142: verification on real runs

Real evaluation of ADR 0013 (semantic constraint coverage) with Qwen 2.5 7B and bge-m3. There are 3 runs per dataset, with the configuration unchanged. Each one is compared case by case with the 3 baseline runs of the previous code (`9b6f609942e8`). No application code, prompt, dataset or golden answer was changed for this analysis.

**Verdict:** TAH-142 meets its acceptance criteria.

- No backend answer presented as complete is false on v3, in any of the 3 runs. The baseline had 10 per run.
- No deterministic regression without a documented reason.
- 2 unjustified abstentions, both correct before by coincidence.
- Isolation is unchanged.

## How differences were attributed

1. **Routes and backend answers are deterministic.** The deterministic harness run before the real runs predicted the route of every case. The real runs match those routes in all 2,514 case-runs (419 cases × 6 runs), and every SQL-route backend answer is byte-identical to the harness output. The only exception is the semantic route's "no information" refusals: the harness has no vectors, so it does not reproduce them.
2. **The model's input did not change.**
   - For all 128 questions answered by Qwen, the query plan is identical under the old and the new parser on every field the old plan had.
   - The selected sources are identical across the 6 runs.
   - The prompt code was not touched.

   Every difference on a Qwen answer is therefore generation variability (temperature 0 on Ollama is not bit-reproducible), not an effect of TAH-142.

## Evaluation errors found

| Check | Error | Effect |
|---|---|---|
| `fact_check.py` id check | Checks inclusion, not equality | Hid 3 false complete lists in the baseline |
| Runner refusal heuristic | A note such as "the context does not contain…" counts as a refusal | **q140 "fixed" is false:** Qwen still writes the marketing email in 3/3 runs, and in `blind-v3-s1` invents a discount code |
| `fact_check.py` on single-payment lookups | Requires amount and status even when not asked | 11 correct Qwen answers counted wrong (q001–q004, q006, q009–q012, q018, q025) |
| `lookup-late-paid` expectation | Expects the word "scaduta" in an answer that states it as "pagato dopo la scadenza" | Stable false failure in the historical set |

The datasets, golden answers and checks are unchanged; these errors are recorded, not corrected.

## Remaining backend answers judged false by the runner (outside v3)

These cases are unchanged by TAH-142 and none states a false figure:

- **lookup-late-paid:** evaluation error, the answer is correct.
- **g-amb-oct28-paid** ("Il pagamento del 28 ottobre è stato pagato?"): answers "no paid payment on 28 October", which is true, without naming the two open payments.
- **g-amb-pro-ok** ("Il pagamento di PayFlow Pro è andato a buon fine?"): lists the 4 paid Pro payments, which is true, while the question is about an unspecified one of 8.

The last two are yes/no questions about "the" payment, where the asked status is used as a filter. → TAH-144

## Isolation

- **From the evaluation:** `isolation` passes in every run: 4/4, 6/6, 5/5 and 150/150. No answer, candidate, selected source or citation in the 24 runs (2,514 answers) contains an id of the other tenant.
- **From the backend tests (not from these runs):** the merchant filter comes from authentication. The parser has no merchant field, and TAH-142 changed no repository, authentication or tenant code.
